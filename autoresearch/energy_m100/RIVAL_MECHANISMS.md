# 成功框架的技术细节(机制层) — deep-research

See findings for the full synthesis of FunSearch, AlphaEvolve, and Eureka mechanisms and the priority ranking for a small-search-space framework.

### FunSearch's islands mechanism is the explicit anti-premature-convergence device: m independent islands; every 4h discard all programs from the worst m/2 islands (lowest best-score) and reseed each with a single copy of the highest-scoring program from a uniformly-random surviving island (ties toward older programs). Cross-island flow happens ONLY at this periodic reset (no continuous migration); the stated purpose is to kill off experiments stuck in local minima. No islands-vs-random delta is reported.
证据:Nature/NSF verbatim: 'Every 4 h, we discard all the programs from the m/2 islands whose best instances have the lowest score. Each of these islands is then seeded with a single program... surviving m/2 islands uniformly at random... single experiments can get stuck in local minima.'
源:https://www.nature.com/articles/s41586-023-06924-6; https://par.nsf.gov/servlets/purl/10499230; https://deepmind.google/blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/

### FunSearch's best-shot prompting samples k=2 programs from a SINGLE island (favouring higher-scoring/shorter), sorts them ascending into versions (v0,v1), and appends a next-version function whose body the LLM completes, so the LLM sees an improving progression and merges the current best rather than resampling blindly. k=2 is empirically justified: two functions beat one, diminishing returns beyond. Precision: the next-version function keeps its header/docstring, only the body is blank. No numeric best-shot-vs-random delta.
证据:Nature: 'we set k = 2, as two functions lead to better results compared to just one, with diminishing returns beyond that.' NSF: 'we first uniformly sample an island and then sample k = 2 programs.'
源:https://www.nature.com/articles/s41586-023-06924-6; https://par.nsf.gov/servlets/purl/10499230; https://arxiv.org/abs/2503.11061

### FunSearch's evaluator produces a fine-grained (non-binary) signal by scoring each program on multiple inputs; the per-input score tuple is the program signature. Programs with identical signatures are clustered, and clusters are sampled via Boltzmann selection (softmax over cluster score with annealed temperature), favouring higher-scoring clusters and shorter programs. This gives a graded score gradient rather than pass/fail, while preserving diversity. Signature is the raw per-input tuple, not an aggregate.
证据:Nature: 'the signature of a program as the tuple containing the program scores on each of the inputs... clustered together... Boltzmann selection procedure.' Annealed temperature confirmed in DeepMind programs_database.py.
源:https://www.nature.com/articles/s41586-023-06924-6; https://par.nsf.gov/servlets/purl/10499230

### The mechanistic reason guided search beats random is attributed to the LLM acting as a mutation/crossover operator carrying semantic code priors, producing better-than-random proposals vs the random operators of classical genetic programming. Islands + fine-grained evaluator amplify it, but the semantic-prior operator is the root cause. Caveat: in SMALL spaces LLM guidance can merely TIE random; the magnitude in a small space is unquantified.
证据:FunSearch: LLM gives 'more effective suggestions than the random ones typically used in genetic programming.' Corroborated by LLEGO and TSGP.
源:https://par.nsf.gov/servlets/purl/10499230; https://openreview.net/forum?id=UyhRtB4hjN; https://arxiv.org/abs/2501.18479

### AlphaEvolve's key improvement over FunSearch is evolving entire code files / multiple components rather than a single function, using EVOLVE-BLOCK-START / EVOLVE-BLOCK-END comment markers and SEARCH/REPLACE diff blocks for precise LLM edits. It adds: (1) a Gemini 2.0 Flash + 2.0 Pro ensemble (Flash high-throughput, Pro occasional higher-quality); (2) meta-prompt evolution (LLM's own instructions co-evolved in a separate database); (3) an evaluation cascade of increasingly hard stages plus optional LLM-generated feedback for qualities like simplicity; (4) an asyncio-distributed pipeline enabling ~100 compute-hours per solution. Database inherits MAP-Elites + island model. Models are Gemini 2.0, not 2.5.
证据:Verbatim: 'special markers (EVOLVE-BLOCK-START and EVOLVE-BLOCK-END)'; 'combination of Gemini 2.0 Flash and Gemini 2.0 Pro'; 'Meta prompt evolution... co-evolved in a separate database'; 'asynchronous computational pipeline (using the asyncio Python library)'; 'on the order of 100 compute-hours'; 'MAP elites algorithm and island-based population models.'
源:https://arxiv.org/abs/2506.13131

### AlphaEvolve's ablation (Section 4, Figure 8) disables each of five components (No evolution, No context, No meta prompt evolution, No full-file evolution, Small base LLM only) and shows each is responsible for a significant improvement. This is QUALITATIVE ONLY: Figure 8 plots metric-vs-compute curves with no per-component numeric deltas, so relative importance cannot be ranked from the paper.
证据:Five component names match verbatim; 'each of the components is responsible for a significant improvement in the results.' No scalar per-component contribution given.
源:https://arxiv.org/abs/2506.13131

### Eureka's reward reflection: (a) LLM exposes each reward as a dictionary of named components, (b) scalar values of every component AND task fitness tracked at intermediate policy checkpoints, (c) summarized as automated text feedback. Exists because scalar task-fitness alone lacks credit assignment. Mutation tips: rewrite entirely if success rates near zero; rescale/rewrite/discard a near-identical component; re-scale a component whose magnitude is much larger than others.
证据:Sec 3.3 + Appendix A Prompt 2: 'tracks the scalar values of all reward components and the task fitness function at intermediate policy checkpoints'; 'the task fitness function itself lacks in credit assignment.'
源:https://arxiv.org/html/2310.12931v2

### Eureka ablations quantify both ingredients. Reward reflection: removing it (feedback reduced to only task-metric F snapshots, evolution retained) drops average normalized score 28.6 percent across Isaac tasks, worse on higher-dim tasks. Evolution: a 32-sample one-shot ablation (same budget as two iterations) performs LOWER than Eureka after just 2 iterations on both benchmarks. The 28.6 percent is the ONLY clean per-component number across all three frameworks.
证据:Sec 4.3: 'reduces the average normalized score by 28.6%'; Fig 5: 32-sample no-evolution 'lower than Eureka after 2 iterations on both benchmarks.'
源:https://arxiv.org/html/2310.12931v2

### Eureka's evolutionary search: K=16 i.i.d. reward candidates per iteration, 5 iterations per run, 5 independent runs per environment. i.i.d. sampling makes the probability all candidates buggy decay exponentially; 16 samples suffices for one executable reward in iteration 1. Uses GPT-4, no task-specific prompting or reward templates (env source code IS provided), outperforming expert human rewards on 83 percent of tasks with 52 percent average improvement across 29 environments spanning 10 robot morphologies.
证据:Verbatim: '5 iterations with K=16 samples per iteration'; 'buggy exponentially decreases'; 'Without any task-specific prompting or pre-defined reward templates'; '83% of the tasks... 52%... 29 open-source RL environments... 10 distinct robot morphologies.'
源:https://arxiv.org/abs/2310.12931; https://arxiv.org/html/2310.12931v2

### The island model recurs across newer LLM-evolution frameworks with concrete copyable hyperparameters. CodeEvolve: 5 islands in a ring topology (cycle graph C5), migrating the top 10 percent every 40 epochs with elitist single-migration (once from origin), plus population control admitting a new individual only if fitness beats the current worst. REvolve: 13 sub-populations, N=5 generations, K=16/generation, pm=0.5, GPT-4 mutation + crossover + periodic migration. Both are adjacent frameworks, not among the three named; cite as transfer targets.
证据:CodeEvolve: '5 parallel islands'; 'cycle graph C5'; '10% top-performing solutions were exchanged... every 40 epochs'; 'migrate once from its island of origin.' REvolve: I=13, N=5, K=16, pm=0.5.
源:https://arxiv.org/html/2510.14150v1; https://arxiv.org/html/2406.01309v2

### Priority order for a small-search-space framework where the LLM is not yet truly in-loop (greedy/random), by cost/benefit: (1) Best-shot prompting with a real LLM in-loop, cheapest/highest leverage since the semantically-primed operator is the documented source of the guided-over-random advantage. (2) Fine-grained multi-input evaluation, needed for a gradient to climb. (3) Reward-reflection-style per-component feedback, the only mechanism with a clean quantified payoff (removing it costs Eureka 28.6 percent). (4) Islands LAST, since benefits scale with search-space size and parallel budget, and no paper quantifies an islands-vs-random delta.
证据:Derived ranking. best-shot = semantic-prior operator; graded signal underpins FunSearch and Eureka selection; reward reflection has the only clean ablation number (28.6 percent); islands unquantified vs random. User's prior finding (LLM ties random in small space) supports this order.
源:https://www.nature.com/articles/s41586-023-06924-6; https://arxiv.org/html/2310.12931v2; https://arxiv.org/abs/2506.13131

## Caveats
Quantitative isolation of mechanisms is scarce. Only ONE clean per-component number exists across all three frameworks: Eureka's 28.6 percent drop from removing reward reflection. FunSearch never reports an islands-vs-random or best-shot-vs-random-resampling numeric delta (k=2 justified only qualitatively). AlphaEvolve's five-way ablation is explicitly qualitative (Figure 8 shows curves; text says each component gives a significant improvement but no per-component deltas), so its additions cannot be ranked from the paper. The LLM-as-semantic-prior-operator mechanism is an attribution, well-supported directionally but with unquantified magnitude, and magnitude is exactly what matters in a small space where the user's own prior work found LLM guidance can merely tie random. Precision points: FunSearch's next-version function is not truly headerless (only body blank); the signature is the raw per-input score tuple, not an aggregate; FunSearch has no continuous migration (transfer only at the 4h reset clone); AlphaEvolve evolves multiple components across a codebase not always whole files, and uses Gemini 2.0 (not 2.5). CodeEvolve and REvolve are adjacent frameworks building on FunSearch/Eureka, not among the three named in the RQ. Sourcing is strong: all 23 claims are 3-0 unanimous and primary-sourced (Nature, arXiv technical reports, DeepMind blog). Time-sensitivity is low for the documented mechanisms.
